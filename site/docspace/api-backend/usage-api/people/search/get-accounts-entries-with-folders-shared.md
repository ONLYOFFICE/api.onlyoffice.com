# getAccountsEntriesWithFoldersShared

> AccountEntryArrayWrapper getAccountsEntriesWithFoldersShared(id, employeeStatus, activationStatus, excludeShared, includeShared, invitedByMe, inviterId, area, employeeTypes, count, startIndex, filterSeparator, filterValue)

`GET /api/2.0/accounts/folder/{id}/search`

Search accounts for a folder

Returns the users and groups that match a search, with whether each one has access to the folder. Requires the right to change the access of the folder. Other callers get 403. If no folder has the ID, the call returns 404. The call is read-only. If `filterValue` is empty, it returns an empty list and a total of 0. The call matches users by first name, last name, or email, and groups by name, ignoring case. Without `filterSeparator`, a user must match every term between spaces. With `filterSeparator`, a user may match any one term. Groups always match the whole text, and they include the system group Everyone. The call returns groups first, sorted by name, and then users. The `count` and `startIndex` parameters page over both together, and the total counts both. The `excludeShared` flag keeps only accounts without access and wins over `includeShared`. The `includeShared` flag filters only users, so groups without access still appear. Groups ignore the user filters, such as `employeeStatus`, `area`, and `employeeTypes`. A caller who is not a DocSpace admin sees only the guests related to them. With `area` set to `All`, they also see guests with access. The `shared` field is also true for the owner and for an account with a record that denies access. A user or a guest can call it for their own folder. They find only the group Everyone and the accounts they work with. These are the owners and members of their rooms, directly or through a group. Accounts with their own record that gives access also count. A record on a parent folder counts too. For another account, they get only the id, names, email, avatars, type flags, status, and `shared`. Only a DocSpace admin can filter by the `inviterId` of another account. For other callers, the call ignores such an `inviterId`. If `count` is out of range, the call returns 400.
