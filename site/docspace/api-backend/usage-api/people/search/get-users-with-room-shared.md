# getUsersWithRoomShared

> EmployeeFullArrayWrapper getUsersWithRoomShared(id, employeeStatus, activationStatus, excludeShared, includeShared, invitedByMe, inviterId, area, employeeTypes, count, startIndex, filterSeparator, filterValue)

`GET /api/2.0/people/room/{id}`

Search users for a room

Returns the portal accounts that match a search, with whether each one has access to the room. Any signed-in user with read access to the room can call it, except a guest. Other callers get 403. If no room has the ID, the call returns 404. The call is read-only. If `filterValue` is empty, it returns every account that matches the other filters. With `excludeShared`, the call returns only accounts without access. With `includeShared`, it returns only accounts with access. If both are set, `excludeShared` wins. Without them, the `shared` field of each profile shows the access. The call does not sort the list. The `count` and `startIndex` parameters page over it, and `total` counts all matches. A caller who is not a DocSpace admin sees only the guests related to them. With `area` set to `All`, they also see guests with access. The `shared` field is also true for the owner and for an account with a record that denies access. A user sees only the accounts they work with. These are the owners and members of the user's rooms, directly or through a group. Accounts with their own record on the room that gives access also count. For another account, a user gets only the id, names, email, avatars, type flags, status, and `shared`. Only a DocSpace admin can filter by the `inviterId` of another account. For other callers, the call ignores such an `inviterId`. If `count` is out of range, the call returns 400. To search users and groups together, use `GET api/2.0/accounts/room/{id}/search`.
