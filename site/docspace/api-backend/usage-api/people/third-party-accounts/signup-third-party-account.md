# signupThirdPartyAccount

> EmployeeWrapper signupThirdPartyAccount(SignupAccountRequestDto)

`POST /api/2.0/people/thirdparty/signup`

Sign up with a provider

Creates an account from a third-party identity and accepts the invitation of `key`. So a person can join by signing in with a provider instead of a password. Pass the `serializedProfile` that the provider sign-in returns. Anyone can call it without signing in. Instead, the call needs the key of a valid invitation link. If the link is invalid or expired, the call returns 403. The invitation link sets the user type of the new account. The value of `employeeType` only selects the kind of link to check. The call changes data. If an account already has this identity or its email, the call links the provider to that account. It then returns that account and creates no second one. So a repeated call with a valid key returns the same profile and sends no emails. If that account is not activated yet, the call returns 403. For a room invitation link, the call also adds the account to the room. A repeat gives the account the room role of the link again. Each call with a room link counts as one use of the link. So after the last allowed use of the link, a repeat returns 403. The call returns 200 with an empty body if the user cancelled the sign-in. The body is also empty if the portal fails to create the account. So check the body, not only the status. A `weixin` or `nextcloud` identity has no email. For it, the portal generates an email, and the account stays in the `AutoGenerated` activation state. The call returns 400 if `key` or `serializedProfile` is missing, or `serializedProfile` is from another portal.  Raises the `user.created` webhook only when the call creates a new account.
